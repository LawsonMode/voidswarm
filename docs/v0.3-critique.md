# Voidswarm v0.3 design review: completeness and consistency

**Verdict.** The four designs are each solid on their own, but they don't fit together yet. There are three different `RoomSettings` extensions, two map dispatchers with different signatures in the same file, two sub-mode catalogs, and three incompatible loot APIs. The Command screen and the Dungeon design also disagree on almost every dungeon rule. On top of that, the total scope is roughly the size of v0.1 and v0.2 combined.

The ARCHITECT has to write one merged contract (§6) before any module agent starts. After that, cut to the v0.3 scope in §4.

### 1.2 Dungeon rules: Command and Dungeon disagree

| Rule | Command | Dungeon |
|---|---|---|
| Parties | 1–4, so max 16 | 1–2, max 8. The 4×4 macro grid and the corner entrances are designed for 2 |
| Timer | 0, or 15–60 min (Rival defaults to 30) | always untimed; instability handles anti-stall |
| Bot fill | a number (4, fallback 2) | ∈ {0, maxPlayers} |
| Drop-in | `nextFloor` through a `queueDropIn` hook | mid-floor: replaces a bot, spawns at the anchor with catch-up XP |
| Which card Rival goes on | PvE (Dungeon Run) | PvPvE card |
| Difficulty labels | Easy/Normal/Nightmare | Story/Veteran/Nightmare |
| Names | "The Descent", "Co-op Descent" | "Rift Run", "Rival Rift", "The Rift" |
| Current floor source | `world.match.floor` | `world.dungeon.floor` (RiftState). `match.floor` never exists |

The user said "dungeon runner", so use **Dungeon Runner** as the card name and "Rift" as the setting.

### 1.3 Objective rules: Command and Objectives disagree

- **Warzone sub-modes.** Command allows only `deathmatch, zones, points`. Objectives adds Warzone CTF and Escort, including a default "Warzone·Escort" room, and builds payload integrity that only exists in Warzone. Under Command's catalog that work is dead code.
- **Team ranges.** Command caps Zones and Points at 2–4 teams. Objectives allows Zones and Hot Point at 2–8, and Hot Point in **FFA**. Command allows FFA only in DM.
- **Limits.** Command has zones 100–2000 (default 400) and points 100–2000 (default 300). Objectives has zones 100–1000 (default 300) and hot point 60–600 (default 200, or 120 in FFA).
- **Length.** Command clamps Arena to 3–20 min. Objectives uses a 12-min CTF default and gives Escort its own round clocks, which Command's `normalizeForType` step 6 would clamp.
- **Host command.** Command uses `/sub`; Objectives uses `/obj`.
- **Default rooms.** There are three different lists: Command's `houseRooms.ts`, the Dungeon design's `server/index.ts` additions, and the Objectives design's "suggested rooms" in `server/index.ts` and LocalTransport.

### 1.4 Loot: three incompatible models

| Aspect | Loot | Dungeon hooks | Objectives hooks |
|---|---|---|---|
| Spawn API | `rollLoot(world, source, x, y, priorityPid)` | `spawnRiftReward(world, source, x, y, team, openerPid)` | `spawnLootCache(world, {tier, source, ownerTeam, lockTicks})` |
| Lock | per player (`reservedFor`, 3 s) | **personal per human**, never shared | **per team** (`ownerTeam`) |
| Rarity | weights plus a floor | ×(1+0.15(f−1)), Nightmare ×1.5, Greed ×1.5; the loot roll has no multiplier input | T1/T2/T3 tier weights |
| Death drop | `spillCarried`: each token scatters, free for anyone | `dropSatchel`: one wreck cache; an ally who picks it up **returns it to the owner** | normal spill |
| Secure | `secureCarried(...,'exit')`, then granted at `enterResults` | `host.secureLoot` **at the moment of extraction** | direct unsecured grants (Escort), which don't exist in Loot's token model |
| Sources | `elite, boss, guardian, floorBoss, chest, shutdown, flag, zone, payload` | `roomChest, treasureChest, eliteChest, keyChest, bossCache, champion` | `ctf_capture, ctf_carrierKill, zone_hold, zone_break, hot_hold, hot_firstCap, escort_*, warzone_hive, match_*` |
| Anti-farm | `lootMult` solo 0.35 (Arena) / 0.5 (Warzone) | — | ≥2 humans and ≥180 s |

Resolution: Loot's `sim/loot.ts` is the only API. Extend it to
`rollLoot(world, source, x, y, {priorityPid, reserveSec, rarityMult, personalFor?})`, and extend `LootSource` to cover the dungeon and objective triggers.

- **Warzone gets nothing today.** Loot's `DROP_RULES` give `flag`/`zone`/`payload` a chance only in `arena`, and there is no Hot Point source at all. Warzone objective play would drop nothing.
- **Double drops.** Dungeon champions are elites, so they hit Loot's 6% `elite` rule and also the Dungeon's guaranteed `champion` drop.

### 1.5 Item and draw catalogs

- The Loot catalog's Rift set (Gravemaw, Veilwright, Riftlance…) and the Dungeon design's §11 draws (Chitin, Brood Pod, Chitin Shard, Spore Burst, Matriarch's Crown, the titles Rift Delver, Deep Diver, Heartbreaker, Lifeline) are **completely different item lists**.
- The Dungeon's Act I "Chitin/Spore" theme collides with Loot's **Swarm** set (Carapace, Spore Wake).
- Loot test-enforces "exactly 15 items per mode set, one per slot", so the Dungeon's roughly 21 items, act trophies and titles cannot be added without breaking that rule.
- Objectives names the sets "Circuit" (Arena) and "Swarmbreaker" (Warzone), and adds an `objectiveFx` slot and "nameplate frames" that Loot doesn't have. Loot calls the sets Gladiator and Swarm.
- **Name collisions.** Loot's `swarm.title` "Exterminator" is also an existing award (Room.ts awards). Objectives' titles Flag Runner, Anchor and Conductor are also its own award names.
- **Command's `drawLabels` fallback is inaccurate.** It lists "Projectile styles · Weapon-fire FX · Nameplates" for Arena, which implies Arena has no hulls or turrets. Loot gives every set all slots. Command also calls `drawsFor(t)`, which Loot never defines; Loot has `SET_INFO[set].featured` (3 items) plus `SET_FOR_TYPE`.
- **Rarity tiers.** Command's chips use 4 tiers (`#9aa4c7/#3bf2ff/#ff5bd6/#ffb347`, CSS `.r-{common,rare,epic,legendary}`, no uncommon). Loot has 5 tiers with different colours. Use Loot's `RARITY_COLORS`.

### 1.6 Files claimed by more than one design (assign one owner and one merge order)

- `sim/mapgen.ts`: Dungeon and Objectives.
- `room/util.clampSettings`: three designs. Merge into Command's `normalizeForType` as the single legality matrix.
- `Room.summary()`, `Room.beginPlaying`, `sendMatchStart`, `buildResult`, `noteEvents`, awards: all four.
- `combat.killShip`: Dungeon's `riftOnDeath` and Loot's `spillCarried` plus shutdown roll.
- `Sim.spawnShip`: Dungeon's `riftSpawnPoint` and Objectives' `objectiveOnRespawn`/`objectiveSpawnPoint`. Precedence is undefined.
- `Sim.step` order. One canonical order is needed:
  `stepProjectiles → stepObjectives → stepRift → stepLoot → bounty → enterFloor → stepMatch`.
  `stepRift` runs extraction, so it must call `secureCarried` before `stepLoot` runs.
- `Sim.stepMatch`: Dungeon's rift outcome and Objectives' `objectiveEndCheck`.
- `codec.ts` and `snapshot.ts`: Dungeon, Loot and Objectives.
- **Hangar.** Command specifies a **`HangarModal`**; Loot specifies **`ui/HangarScreen.ts` as a `'hangar'` view state** in main.ts. Pick the modal, which keeps `computeScreen` purely derived from state.
- `ui/TitleScreen.ts`: Command (`showView`, `logout`, "Enter Command") and Loot (guest copy). Both are blocked on the in-flight edit; do one pass with one owner.
- `ui/Overlays.ts`: Command's CreateGameModal, Dungeon's "rift preset", and Objectives' OBJECTIVE_INFO picker.
- Hud top-centre: the Dungeon's boss bar and strip, the Objectives strip, and Loot's tray and banners compete for the same space.
- **Guest copy contradicts itself.** Command says "drops you find won't be saved". Loot says "items stay on this device and only you see them".

## 3. Things that won't work with the current code

1. **Spectators evict bots.** `syncBots` computes `s.maxPlayers - allHumans`, and `allHumans` includes spectators (Room.ts:496). Command's `SPECTATOR_SLOTS` lets humans exceed `maxPlayers`, so every Watch removes a bot from the live match. Change the cap to `maxPlayers - activeHumans`.
2. **Ghosting.** `SnapshotBuilder.build` filters cloaked ships only when `me` exists (snapshot.ts:150). Spectators, now open to anyone through Watch, see cloaked opponents. A second guest tab can scout for a PvP team. Filter cloak for spectators, or refuse Watch in rooms where the same account or IP is playing.
3. **Untimed matches.** `matchSeconds 0` gives `endTick 0` (world.ts:39). `timeLeftSec` then becomes `max(0, …) = 0` (snapshot.ts:130), and the HUD shows a red "0:00" (Hud.ts:168-169). Add `timed: boolean` to `MatchView`, or send −1.
4. **teamCount 1.** It's clamped at Sim.ts:60, and also in `generateMap` (map.ts:28, `1→2`). Any co-op fallback that uses `generateMap` gets a 2-base map.
5. **Medics revive extracted pilots.** `fieldRevive` revives any dead ship near an alive Medic (Sim.ts:237). Extracted pilots are `alive=false` and stay in `world.ships`, so they would be revived back into the rift after banking. Skip ships with `rOut`, and ships benched during an escort intermission.
6. **Class and team change teleports and heals.** `setShipClass` and `setPlayerTeam` call `spawnShip` with no `at` (Sim.ts:179-200), which sets full energy, sends you to the team spawn and gives invulnerability. With loot, a carrier swaps class and is instantly at base to bank. In a dungeon it escapes a sealed room and heals. In Rival it lets you hop parties. During `playing`, either lock class and team changes (dungeon), or keep position and energy fraction and apply the change at the next respawn.
7. **0–0 objective results.** `buildResult` falls back to kill-score team sums when the sim's teamScores sum to 0 (Room.ts:753-754). A 0–0 CTF ended with `/end` is won by kills. Objectives mentions this, but the fix has to be in Room.
8. **Idle bots-only matches keep running, and untimed ones never end.** `Room.tickPlaying` doesn't check humans (Room.ts:833+), and house rooms never close (Zone.ts:179-188). With 8 online house rooms plus overflow, up to `MAX_ROOMS` 24 sims can run at about 4 ms each on a single thread (ARCH §6). That is far over the 16.7 ms tick budget. **A bots-only untimed dungeon runs forever.** The same thing happens offline: leaving a match to go back to Command leaves its sim running in the browser. Fix: abort to lobby after about 10 s with no humans, and cap concurrently *playing* rooms (for example 6).
9. **Tail encoding is explicit.** `encodeSnapshot` builds `tailObj = {you, match, events, xs, xk}` (codec.ts:92). Top-level `Snapshot.loot`/`carry` need codec code; things nested under `match` and `you` ride along for free. Also, `JSON.stringify` of the shared `match` runs once per viewer per snapshot. Pre-serialise it once in `prepare`, because Rift and Objective views make it 2–4× larger.
10. **Appending to `EnemyKind` breaks the build** until three exhaustive Records are updated: `ENEMY_DEFS` (enemies.ts:24), `ENEMY_COLORS` (palette.ts:25) and `demo.ts:97`. They have different owners (PVE and RENDER). The ARCHITECT should land the union together with placeholder entries.
11. **Required new fields break typecheck** (typecheck is part of DoD). Loot's `Ship.carried` and `World.loot` are required, but Ship literals exist in bots.test.ts:65-81, pve.test.ts:55-65 and room.test.ts (FakeSim). Make them optional, or update the tests.
12. **room.test.ts mocks `Sim`** (`vi.mock('../sim/Sim')`, lines 3-40). New Room calls to `sim.setLootMult`, `sim.takeCarried` and `sim.abandonRift` will throw in every existing room test unless FakeSim gains them, or Room calls them with `?.()`.
13. **Nav cache.** `getNavGrid` caches per `GameMap` in a WeakMap (nav.ts:41-49). In-place door seals go stale unless `rev` is added; the Dungeon design covers this. `walls.ts` treats tile 4 as floor (walls.ts:12) and bakes at `setMap`, so doors need the dynamic overlay the Dungeon proposes.
14. **Loot is predictable from `mapSeed`.** Loot seeds `lootRng` from `mapSeed ^ 0x1007ee7`, and `mapSeed` is sent to every client in `matchStart` (Room.ts:645). Clients can pre-compute every cache's chance, rarity and set. The Dungeon design explicitly requires a server-only `lootSeed`. Add `SimConfig.lootSeed` from `crypto`, and never send it.
15. **Dungeon entrances count as a "base".** Loot banks on any team-owned `TILE_BASE` in teams mode. Dungeon entrances are `TILE_BASE` pads in teams mode, so players could bank at the entrance and bypass extraction. Gate banking on `gameType !== 'dungeon'`.
16. **The per-match cache cap starves deep floors.** `min(72, 8+4·humans)` gives 12 for solo and 24 for 4 humans. A 6-floor rift has about 6–8 chests per floor plus bosses and personal drops, so the cap is hit around floor 2–3 and "push deeper for better drops" gives nothing. `MAX_CARRIED = 8` has the same problem between extraction floors, which are 3 apart. Both need dungeon-specific values.
17. **Grant idempotency drops loot.** `grantKey = ${matchId}#${playerId}`, and Loot claims a rejoin gets a new playerId. That's wrong: `playerId` is per *connection* (Zone.ts:267). A player who leaves the room (bank granted) and drops back into the same match keeps the same key, and the final grant is silently discarded by `INSERT OR IGNORE`. Dungeon extraction granting mid-match has the same collision. Add a per-join sequence to the key, or grant once only.
18. **Grant failures abort the match.** `enterResults` runs inside `Room.tick`. A thrown `ProfileConflict` or SQLite error goes to `onTickError`, and after 60 of them the match is aborted (Room.ts:~930). Wrap `grantLoot` in try/catch.
19. **The second SQLite connection** must also set `PRAGMA foreign_keys=ON`, or `ON DELETE CASCADE` on `loot_ledger` is inert. The `profile_json` column exists and is NULL (store.ts:30), so the migration plan is sound. auth.test.ts's `user_version toBe(1)` (~line 505) must change.
20. **Accept only valid join intents.** `validateClientMsg` passes extra fields straight through (validate.ts). Whitelist `intent ∈ {lobby, play, watch}` so a client can't send the server-internal `'quick'`. `quickPlay` and the 4 loot messages must be added to `KNOWN` (validate.ts:5-8), or they are silently dropped.
21. **Latent: u16 `playerId` on the wire.** `qU16` clamps rather than wraps (codec.ts:112), and Loot adds another u16 pid field (`reservedFor`). Every bot add allocates a new pid (Room.ts `addBot`), so house rooms and quick-play churn make 65,535 reachable on a long-running server. Recycle pids, or widen the field in the VERSION 4 bump.
22. **Colour checks are too weak.** Loot's readability test only rejects exact `TEAM_COLORS`/`ENEMY_COLOR` matches. Rift `DEEP 0x6a4bff` is almost identical to the blackhole enemy `0x7a5bff`; Rift `VIOLET 0x9d6bff` is close to team Violet `0xb05bff`; Gladiator `GOLD 0xffc53d` is close to team Solar `0xffd43b`. Test hue distance against every `ENEMY_COLORS` and `TEAM_COLORS` entry. Command's card accents `0x3bf2ff` and `0xff5bd6` are exactly team Cyan and Rose; that's acceptable for UI but worth noting.
23. **Co-op results chat is wrong.** `enterResults` prints "Team Crimson wins!" or "draw" (Room.ts:~699-701). A co-op clear would say "Team Crimson wins!" and a wipe would say "draw". Add PvE outcome lines.
24. **Dungeon HUD shows tier as wave.** The Dungeon repurposes `world.pve.wave` as tier, so `MatchView.wave` and any "Wave N" HUD text show the tier. Hide it when `match.dungeon` is set.

## 4. Scope: what to cut to v0.4 while keeping every game type playable

v0.2 is about 21k lines. The four designs together likely add a similar amount across 7 agents. Proposed v0.3:

| Topic | Keep in v0.3 | Cut to v0.4 |
|---|---|---|
| **Command** | Cards, live list, Quick Play, Create, Join, Watch (with fixes #1 and #2), house rooms (**5 online**: Descent, Flag Run, Hot Points, Duel Pit, Warzone Classic), offline 3 rooms, bots-only abort | Rotating featured draws; phone segmented tabs (use a stacked layout); Pilots Online panel |

Suggested milestones, each shippable:
- **M1.** Contract, Command, DM/Classic, PROTOCOL 3.
- **M2.** Loot core, persistence and Hangar.
- **M3.** CTF, Zones and Hot Point, including AI goals.
- **M4.** Dungeon co-op, including rift bots.

## 5. Missing pieces

- **Bots in dungeons.** Riftgoals (follow the party, rescue, advance) are designed, but Command ships `coop.ready` gated on them and falls back to botFill 2. Say explicitly that dungeon Quick Play is disabled until bots can clear floor 1 (the Dungeon's bots.test).
- **Bots and objectives.** Objective AI must land *before* `ready=true`, because house rooms are bot-filled. Nobody owns an "AI parity" acceptance test per sub-mode; add one to smoke.
- **Offline.** Offline needs:
  - the bots-only abort from §3 #8;
  - LocalProfileStore injection into the LocalTransport Zone (LocalTransport.ts:18-23);
  - offline house-room names decided in one place;
  - which offline sub-modes exist when objectives aren't ready (Command's `firstReadySubMode` substitution is good, so keep it).
- **Codec and bandwidth.** Do a single VERSION 4 bump covering the enemy kinds, the loot section, a `carry` tail and optionally u32 playerIds. Estimated tail growth is +0.5–1 KB per snapshot in the dungeon plus loot case. Send `RiftView.rooms`/`chests` only when they change. Pre-serialise `match` (§3 #9).
- **Security.**
  - Server-only `lootSeed` (§3 #14).
  - Whitelist join intents (§3 #20).
  - Spectator cloak leak (§3 #2).
  - Class-swap and team-swap teleports (§3 #6).
  - Solo-dungeon farming: `LOOT_MULT_SOLO.dungeon = 1`, chests at 100%, a 3-floor Story run. Decide whether that is fine.
  - Alt-account bypass of the solo penalty is an accepted risk; say so.
  - Guests roll against an empty server profile, so their device duplicates are never rerolled.
  - Dungeon floors are generated client-side from the seed, so "fog" and the treasure and key room locations are client-knowable. Keep chest *contents* server-side, which they already are.
- **Persistence.** `commitGrants` should be the *only* write path at match end, with no `save` in the same tick. Document a single-process assumption in ARCHITECTURE §3c. Decide how `PROFILE_VERSION` migrations work (normalize-on-read is fine), and write a test for "v > PROFILE_VERSION stays read-only".
- **Reconnect and disconnect.** Loot treats a disconnect as leaving. The Dungeon has no reconnect story either. Mention it as out of scope.
- **Docs and versioning.** ARCHITECTURE.md needs one merged rewrite: §3 Game types, §3 Dungeon Runner, §3c Loot, §4 Title→Command→Room→Match→Results, §5 wire, and the §1 ownership table with `data/gameTypes.ts`, `room/houseRooms.ts`, `sim/objectives/*`, `sim/loot.ts`, `profile/*`. Also bump `package.json` to 0.3.0 (MINOR) and update the project CLAUDE.md summary.

## 6. Decisions the ARCHITECT should freeze in one contract pass

1. **`RoomSettings` += `gameType, subMode, floors, objectiveLimit`.** Drop `objective` and `riftFloors`. `scoreLimit` is DM-only. Put a `DEFAULT_SETTINGS_BY_TYPE` in protocol.ts.
2. **`SubMode` = `coop | rival | deathmatch | ctf | zones | hotpoint | escort`.** One catalog in `data/gameTypes.ts`. Arena gets DM, CTF, Zones, Hot Point (Escort in v0.4). Warzone gets Classic and Zones. Team ranges: CTF 2–4; Zones and Hot Point 2–8; Hot Point also FFA.
3. **Dungeon:** `floors ∈ {3,6}` (9 in v0.4), untimed, parties 1 (2 in v0.4), botFill numeric, drop-in at floor start, card "Dungeon Runner" under PvE.
4. **`SimConfig` += `gameType, subMode, floors, objectiveLimit, lootMult, lootSeed`**, all optional. `World.dungeon?`, `World.objective?` and `World.loot?` optional as well.
5. **`matchStart` += `gameType, subMode, floor`**, plus a new `floorStart` message. One `buildMatchMap({seed, gameType, subMode, teamCount, floor})` in `sim/mapgen.ts`, owned by SIM.
6. **`RoomSummary.live`** = `{elapsedSec, timeLeftSec (-1 untimed), wave, floor, floorsTotal, scores, scoreline, leader, leaderScore}`. `MatchView` += `timed`.
