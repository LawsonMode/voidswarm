### 1.3 How the conflicts were resolved

**A. Contract shape**

| Topic | Decision |
|---|---|
| Sub-mode field | `RoomSettings.subMode: SubMode`. There is no separate `objective` field. |
| Sub-mode ids | `coop \| rival \| deathmatch \| ctf \| zones \| hotpoint \| escort`. The Hot Point id is `hotpoint`, not `points`. |
| Objective target | `objectiveLimit`. `scoreLimit` applies only to Deathmatch. |
| Floors | `floors` ∈ {3, 6}. Default is 6, so there is a real choice at floor 3: extract, or go deeper. There is no `riftFloors` field. |
| `SimConfig.gameType` when absent | `gameTypeOf()` returns `pve > 0 ? 'warzone' : 'arena'`. Room always passes it explicitly. |
| Map dispatcher | One function: `buildMatchMap({seed, gameType, subMode, teamCount, floor})` in `sim/mapgen.ts`, owned by SIM. |
| Sub-mode metadata | One catalog, `data/gameTypes.ts`. `OBJECTIVE_INFO` is merged into `SubModeDef`. |
| Live room data | One `RoomSummary.live` block. It absorbs `scoreline`, `floorsTotal` and `lives`. |
| Party constants | `PARTY_SIZE = 4`, `MAX_PARTIES = 2` (ceiling). v0.3 co-op uses 1 party. |
| Loot API | Only `sim/loot.ts` (`rollLoot` / `spillCarried` / `secureCarried`). `spawnRiftReward`, `dropSatchel` and `spawnLootCache` are dropped. |
| Death drop | The Loot model: each cache scatters. An ally who picks one up keeps it; there's no return to the owner. |
| Securing vs granting | Caches are **secured** at extraction or match end. They are **granted exactly once** at results, or when the player leaves, with a join sequence in the grant key. |
| Item catalog | The Loot catalog, trimmed to 13 items per set. Item ideas from the Dungeon and Objectives designs go into the v0.4 backlog. |
| Rarity | 5 tiers. `RARITY_COLORS` from `data/loot.ts` are used everywhere, including the Command CSS. |
| Hangar | `HangarModal`. There is no `'hangar'` screen state, so `computeScreen` stays purely derived. |
| Codec / protocol | Codec VERSION 4 exactly once (enemy kind, loot section, `carry` tail, u32 playerId, `'striker'` fallback fixed to `'brute'`). PROTOCOL_VERSION 3 exactly once. |
| Card name | "Dungeon Runner". Rival Rift will go on that card with a PvPvE badge in v0.4. |
| Dungeon difficulty labels | Story / Veteran / Nightmare |
| Dungeon drop-in | At the start of a floor only. |
| Guest copy | "Items you find stay on this device and only you see them." |
| Dungeon floor source | `world.dungeon.floor`. There is no `match.floor`. |

## 2. Player flow

### 2.1 Login (already built; v0.3 changes only the landing screen)

- **Log in:** Username + Password + [Log in]. Links underneath: Create account · Forgot password? · Continue as guest · Play offline. This is the existing `TitleScreen.ts` loginForm.

  - New public `logout()` (used by the Command top bar).
  - Guest copy: "Items you find stay on this device and only you see them. Create an account to keep them everywhere and show them off."

### 3.2 Settings normalization (`room/util.ts`, ROOM)

**`clampSettings(base, patch)`** runs in this order:

1. **Type switch.** If `patch.gameType` is valid and differs from `base.gameType`, re-base on `{ ...DEFAULT_SETTINGS_BY_TYPE[t], name: base.name, botSkill: base.botSkill }`.
2. **Sub-mode switch.** If `patch.subMode` is valid and differs from the current one, reset `matchMinutes` to `SUB_MODES[s].defaultMinutes` unless the patch sets it, and reset `objectiveLimit` to 0 unless the patch sets it.
3. **Parse fields with wide raw bounds:**
   - teamCount 1–8, maxPlayers 1–32, botFill 0–32
   - matchMinutes 0–60, floors 0–10, objectiveLimit 0–5000
   - scoreLimit 0–100000, pveIntensity 0–3
   - name (≤ 32 chars), mode, botSkill, friendlyFire
4. Call `normalizeForType(out)`.

**`normalizeForType(s)`**, with `T = GAME_TYPES[s.gameType]`:

1. If `s.subMode` isn't in `T.subModes`, set it to `T.defaultSubMode`. Then if it isn't `ready`, set it to `firstReadySubMode(t) ?? s.subMode`. Zone refuses to create a room whose type has no ready sub-mode.
2. Allegiance. With `D = SUB_MODES[s.subMode]`: dungeon forces `'teams'`, and `ffa` without `D.ffa` becomes `'teams'`.
3. `teamCount`: in teams mode, clamp to `[D.minTeams, D.maxTeams]`. In FFA, clamp to [2, 8] so the value is kept for switching back.
4. `maxPlayers`: clamp to `[T.minPlayers, T.partySize ? s.teamCount × T.partySize : T.maxPlayers]`.
5. `botFill = min(botFill, maxPlayers)`.
6. `matchMinutes`: 0 if `T.untimed`, else clamp to `[T.minutesMin, T.minutesMax]`.
7. `pveIntensity`: 0 if `T.pve === 'off'`, else clamp to [1, 3].
8. `floors`: dungeon snaps to the nearest `RIFT_FLOOR_OPTIONS` entry (ties go lower; 0 becomes 6). Other types get 0.
9. `objectiveLimit`: 0 if `D.limitMax === 0`, else keep 0 or clamp to `[D.limitMin, D.limitMax]`.
10. `scoreLimit = 0` unless `subMode === 'deathmatch'`.

The existing tests stay green, because the absent/base type is Warzone DM: teamCount 1 → 2, 99 → 8, maxPlayers 500 → 32, matchMinutes 0 → 1, mode `'nope'` → base.

**Lobby-only fields:** `gameType`, `subMode`, `mode`, `teamCount`, `floors`. Changing them outside the lobby reverts and tells the host. `matchMinutes`, `objectiveLimit`, `scoreLimit` and `botFill` take effect at the next match.

### 3.4 Quick Play (`quickPlay {gameType, subMode?}`)

`quickPlayScore(summary, t, sub?)` returns −1 when the room is not eligible: the type or sub-mode doesn't match, `!SUB_MODES[sub].ready`, or `!joinable`. Otherwise:

| Phase | Base | Excluded when |
|---|---|---|
| countdown | 130 | — |
| lobby with auto-start pending | 120 | — |
| lobby | 100 | — |
| results | 60 | — |
| playing, `dropIn: 'any'` | 80 | `live.timeLeftSec` ∈ [0, 90) |
| playing, dungeon | 40 | on the last floor, or the portal is departing |

**Score = base + 10·min(activeHumans, maxPlayers − 1) + 5 if a house room.** Ties go to the earlier room.

Steps:
1. Join the best room with the server-internal intent `'quick'`.
2. If no room is eligible, create an overflow room `{gameType, subMode: sub ?? firstReadySubMode(t)}`, named `${T.houseName} · ${SUB_MODES[s].short} #k`. It is `userCreated`, so it closes after 60 s empty.
3. Errors:
   - No ready sub-mode: `"<Type> isn't open yet."`
   - Online and `rooms ≥ MAX_ROOMS`: `"All game slots are busy — try again in a moment."`

### 3.5 Join, Watch, seats

- `joinRoom {roomId, intent?: 'lobby'|'play'|'watch'}`. `validate.ts` accepts only those three values. `'quick'` is never accepted from the wire.
- **Room fields:**
  - `activeHumans` = humans who are not spectating.
  - `joinable` = `activeHumans < maxPlayers && humans < maxPlayers + SPECTATOR_SLOTS`.
  - `watchable` = `humans < maxPlayers + SPECTATOR_SLOTS && phase === 'playing'`.
- **`canJoin(intent)`:** `'watch'` uses the watchable rule. Everything else uses `joinable`. It replaces `isFull()` in `Zone.joinRoom`/`addUser`.
- **`onJoinIntent(user, intent)`:**
  - **watch:** team becomes `TEAM_UNASSIGNED` and spectating; if playing, `joinMatch` as a spectator. Online, it is refused ("Can't watch a room you're playing in from the same network") when another connection with the same `address` is an active player in that room.
  - **play / quick while playing:**
    - Arena and Warzone: auto team (`smallestTeam`, or `NO_TEAM` in FFA), then `joinMatch`.
    - Dungeon: `pendingDropIn = true`. The player spectates now, and is added at the next `floorStart` (replacing a bot if the party is full).
  - **quick in lobby or countdown:** `ready = true`, so the existing 20 s auto-start runs. Offline in the lobby, call `startCountdown()` immediately.
  - Always `tell` a one-line summary, e.g. "Quick Play → Flag Run (CTF). Auto-start in 20 s — un-ready to wait."
- **`syncBots` (fix #1):** `want = max(0, min(botFill, maxPlayers) − activeHumans)`.
- **Spectator cloak (fix #2):** in `SnapshotBuilder.build`, when `me` is null, drop every ship that has `SHIPFLAG_CLOAKED`.

### 3.6 Room lifecycle guards (server CPU)

- **Bots-only abort.** In countdown or playing, if the room has had 0 humans (spectators included) for `BOTS_ONLY_ABORT_SEC = 10`, call `backToLobby()` silently: no results, no grants. This also stops the offline sim you left behind when you go back to Command.
- **Playing cap.** Online, before starting a countdown, the room calls `host.canStartMatch()`. If ≥ `MAX_PLAYING_ROOMS = 6` rooms are in countdown or playing, the room stays in the lobby, says "All arenas are busy — launching as soon as one frees up", and re-checks every second. Offline, the bots-only abort already keeps it to one.
- **Live list refresh.** In Zone housekeeping: if nothing is dirty, but ≥ `ROOM_LIST_LIVE_SEC · 60` ticks have passed since the last push, some room is playing, and some user is in the zone lobby, mark the room list dirty. Structural changes still push within 1 s.
- When `autoStartTicks` goes from 0 to 1, the room calls `host.roomsChanged()` so the list shows "Starting in".

## 4. Dungeon Runner spec (the Rift, co-op, v0.3)

**Pitch.** A party of 1–4 pilots, with bots filling empty seats, dives through 3 or 6 procedurally generated floors.
- Combat rooms seal their doors until the room is cleared.
- Reward chests, treasure branches and a key room open the Descend portal.
- **Floors 3 and 6 end in the Matriarch boss.** Beating her opens **Extract** next to Descend: bank your caches and leave, or push deeper.
- Deaths cost a shared lives pool. At 0 lives you sit out until the next floor.
- Your unsecured caches spill when you die.

Everything below is gated on `world.dungeon`, and the Arena/Warzone code paths are untouched.

### 4.1 Run structure

| Setting | Value |
|---|---|
| Floors | 3 (Short, ~15 min) or 6 (Standard, ~30 min) |
| Biome | floors 1–3 `hive` · floors 4–6 `prism` (palette and pillar style only) |
| Boss / extraction floors | `floor % RIFT_BOSS_EVERY (3) === 0` |

### 4.2 Floor generation (`sim/floorgen.ts`, SIM)

`generateFloor(seed, floor, parties): GameMap` is deterministic. It uses only `Rng` and `hash32` (`util/hash.ts`), and both hosts call it through `buildMatchMap`.

**Fixed geometry.** Every floor uses the full 200×200 tile grid (32 px tiles, 6400 px), matching `MAP_SIZE`. Unused space is `TILE_ROCK`. Because the grid size never changes, `world.grid` and the sim side-state cells stay valid across floor swaps.

**Macro grid.** A 4×4 grid of 50×50-tile cells, one room per used cell.

| Room kind | Interior (tiles) | Sealable | Contents |
|---|---|---|---|
| entrance | 22–24² | no | `TILE_BASE` pad (no enemy spawns); 6 party spawns on a ring of r = 110 px |
| hall | 24–32 | no | dormant pack(s); 4 spawn markers; 1–3 pillars |
| arena | 34–42 | **yes** | 8 markers; 3–6 pillars; 1 reward chest (`roomChest`) |
| treasure | 16–20 | no | 2 chests (`treasureChest`); 50% chance of a dormant guard pack |
| key | 40–44 | **yes** | pulses + mini-boss → Descend portal; 1 chest (`keyChest`) |
| boss | 46×46 | **yes** | Matriarch → Descend (non-final floor) + Extract; `bossCache` on kill |

**Rooms per floor** (fixed order along the main path; H = hall, A = arena, T = treasure branch):

| Floor | Total | Main path | Branches |
|---|---|---|---|
| 1, 2 | 7 | entrance, H, A, H, A, key | T |
| 3 | 8 | entrance, H, A, H, A, H, **boss** | T |
| 4 | 9 | entrance, H, A, H, A, A, key | T, T |
| 5 | 9 | entrance, H, A, A, H, A, key | T, T |
| 6 | 10 | entrance, H, A, H, A, H, A, **boss** | T, T |

**Algorithm**
1. `seed' = hash32(seed, floor, parties)`. Up to 8 attempts, each with `Rng(seed' + k·0x9e3779b9)`. The first layout that validates is accepted. A hard-coded snake layout is the guaranteed fallback.
2. Entrance = a random edge cell. Key/boss = the cell at maximum BFS distance (rng breaks ties).
3. The main path is a randomized self-avoiding DFS of exactly the listed length. Branches are single dead-end cells next to the main path, never next to the key/boss room.
4. **Carve.**
   - Fill with ROCK. Jitter each interior inside its cell by ±⌊(50 − 4 − size)/2⌋. Give it a 2-tile `TILE_WALL` rim; the interior is EMPTY (BASE for the entrance).
   - Corridors are 5 tiles wide, L- or Z-shaped, between door points on the facing walls (≥ 4 tiles from corners). Rock 8-adjacent to a corridor becomes `TILE_WALL`.
5. **Doors.** Where a corridor crosses a sealable rim, the 5×2 gap becomes `TILE_DOOR`. Record `RiftDoor {tiles, inX, inY}`, with the in-point 3 tiles inside the room.
6. **Decor.**
   - `hive`: round ROCK pillars with r 1.5–2.8 tiles.
   - `prism`: 3×3 WALL square pillars.
   - Pillars stay ≥ 6 tiles from doors and ≥ 7 tiles from the room centre. Boss rooms get 4 symmetric pillars at 30% of the half-size.
7. **Markers.**
   - Enemy spawns on a ring at 0.72 × half-size: 8 per sealable room, 4 per hall, 3 per treasure room. Each must be an open tile ≥ 7 tiles from any door.
   - Chests: sealable rooms get one at centre + (0, 128 px). Treasure rooms get two at 0.4 × half-size.
   - Portal at the key/boss centre. Extract (boss floors only) at centre + 352 px, on the side away from the first door.
8. **Validate.** Flood fill with doors open: every centre and marker must be reachable and on an open tile, no rooms overlap, and every sealable room has ≥ 1 door.
9. **Budget:** < 15 ms.

Helpers:
- `roomAt(map, x, y)` returns a room index, or −1 for corridors.
- `riftTier(f) = 1 + 2·(f − 1)`.
- `applyRoomSeals(map, states)`: writes TILE_WALL into the door tiles of rooms that are ARMING→SEALED (state 2) and TILE_DOOR otherwise. It is pure and idempotent, returns `changed`, and increments `map.rev` on change. **It is the only runtime tile mutation.**

### 4.3 Room state machine (`sim/dungeon.ts`, SIM)

States: `DORMANT 0 → ARMING 1 → SEALED 2 → CLEARED 3`. A non-sealable room goes DORMANT → CLEARED the first time a ship enters. That drives the minimap reveal (`party.seen`) and the room counter.

- **Trigger.** An alive, free (not attached), non-extracted ship enters the interior, inset by 3 tiles (5 for the boss room). The room goes to ARMING with `until = tick + 1.5 s` and emits `roomSeal{sec: 1.5}`. Arming cannot be cancelled.
- **Seal at `until`:**
  1. `applyRoomSeals`.
  2. **Doorway nudge:** every ship or enemy overlapping a door tile moves to that door's in-point, with ±40 px jitter.
  3. **Recall:** every alive, free party ship outside the room teleports to a door in-point (50–90 px ring, open tiles) and emits `blink`.
  4. PVE `riftEncounterStart(world, room, n)`, where n = alive non-extracted party ships.
  5. Emit `roomSeal{sec: 0}`.
- **Clear.** The room clears when `riftEncounterDone()` is true: all pulses have spawned and **no enemy is inside the room rect** (a positional check).
  - Unseal. `anchor = centre + (0, −120 px)`.
  - Each party ship inside gets +25 score and `grantXp(12·tier)`. `roomsCleared++`.
  - The chest becomes openable. Emit `roomClear`.
  - Key room: `portal = 1`.
  - Boss room: `portal = 1` if not the final floor, `extractOpen = true`, `lives += 2`, `bossesKilled++`, and emit `portalOpen` for each portal.
- **Regroup (the downed/rescue replacement).** A SEALED room with no alive sealing-party ship inside for `RIFT_REGROUP_SEC = 2` s resets:
  - Enemies inside are removed and the room goes back to DORMANT, unsealed.
  - `riftEncounterReset` runs. Chest bits persist. Emit `roomReset`.
- **Chests.** A ship within 48 px of an unopened chest opens it. Treasure chests open any time; reward and key chests only after the room is CLEARED. Opening:
  - sets the room's chest bit;
  - emits `chestOpen`;
  - calls `rollLoot(world, source, x, y, { priorityPid: opener, personalFor: <humans of the party> })`.

  If loot is not implemented yet (before M2), the fallback is `dropGems(20·tier)`.

### 4.4 Encounters and the rift director (`sim/pve/rift.ts`, PVE)

`stepDirector` returns early when `world.dungeon` is set, so no `waveStart` fires. `pveStep` runs `stepRiftDirector` first. `world.pve.wave` is repurposed as the **tier**, so the existing `spawnEnemy`/hpScale scaling applies unchanged. The HUD hides "Wave" in dungeons (fix #24).

| Floor | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| Tier | 1 | 3 | 5 | 7 | 9 | 11 |
| Enemy HP × (1 + 0.12·(t − 1)) | 1.00 | 1.24 | 1.48 | 1.72 | 1.96 | 2.20 |
| Pulses per arena | 3 | 3 | 3 | 4 | 4 | 4 |
| Solo pulse size (8 + 2f) | 10 | 12 | 14 | 16 | 18 | 20 |

**Scaling**
- Party, where n = party ships at seal time: count × (1 + 0.3(n − 1)); HP × (1 + 0.25(n − 1)); boss HP × (1 + 0.6(n − 1)).
- Difficulty:
  - Story: HP ×0.7, count ×0.8, lives +2.
  - Veteran: ×1.
  - Nightmare: HP ×1.4, count ×1.25, lives −2 (minimum 2).

**Kind weights (replace `pickKind` in rifts)**
- Floor 1: drone 10, dart 4, weaver 3.
- Floor 2+: add splitter 3, spinner 2.
- Floor 3+: add brute 1.2.
- Floor 5+: add blackhole 0.3 (max 1 per room).
- Biome ×1.5: hive → drone/splitter; prism → spinner/weaver.
- The existing 5% elite formation chance stays.

**Pulses**
- Pulse k uses ⌈count/6⌉ spawn markers, preferring those ≥ 260 px from every ship.
- Emit `spawnWarn{radius: 90, sec: 0.8}`, then `spawnFormation` 48 ticks later.
- The next pulse fires when enemies alive in the room ≤ 30% of the last pulse, or 14 s have passed, with a minimum gap of 3 s.

**Scripts**
- **Hall:** dormant packs of (4 + f), 2 packs on floor ≥ 4 plus a spinner. `mem.sleep = 1` means no AI and no contact damage. They wake on room entry, a ship within 600 px with line of sight, or damage.
- **Treasure:** 50% chance of a dormant guard pack: (3 + ⌊f/2⌋) weavers + 1 spinner, at tier + 1.
- **Arena:** pulses.
- **Key:** pulses, then a mini-boss as the last pulse. Floors 1–2: an elite brute. Floors 4–5: a `hive` at HP ×0.8.

**Leash.** In a rift, `retarget` only considers ships in the same `roomAt` room, or ships ≤ 900 px away with line of sight. An enemy with no target steers home (`mem.hx/hy`).

**Instability.** After `RIFT_SOFT_LIMIT_SEC = 420` s on a floor (warning banner at 360 s):
- Every 25 s a hunter pack of (4 + f) darts/weavers at tier + 2 spawns 700–1100 px from a random active ship that is not in a sealed room.
- Enemy HP +10% per extra minute.
- Emit `instability`.

### 4.5 The Matriarch (`sim/pve/bosses.ts`, PVE; `EnemyKind 'matriarch'`)

Base: radius 88, HP 30000, speed 60, contact 320, XP 150, score 150. Radius stays ≤ `MAX_RADIUS` 90. Tier and party scaling apply on top. A 3 s `bossIntro` (`mem.dmgTaken = 0`, camera shake) comes first.

| Phase | Behaviour |
|---|---|
| P1 (100–66%) | Hive script: drones every 3.0 s (4 + party); a 20-shot ring every 4.5 s (speed 240, damage 80) |
| P2 (66–33%) | **Brood Burst:** 3 splitters at the densest ship cluster every 8 s. Rings become double rings 0.35 s apart with a 60° gap. |
| P3 (< 33%) | **Frenzy:** every 6 s a 0.8 s line `telegraph`, then a 0.6 s dash at 900 px/s. Drones every 2 s. Each wall impact spawns 4 splitlings. |
| Floor 6 variant | Tier 11, plus one `hive` add (HP ×0.6) at the 66% and 33% thresholds (respects MAX_HIVES 2) |
| Death | The existing Hive splash (400 damage, r 300); `bossCache` for every human of the party |

`damageEnemy` multiplies the amount by `enemy.mem.dmgTaken ?? 1` (SIM change in `combat.ts`). A `bossPhase` event fires on each transition.

### 4.6 Party, lives, death

- **Lives** are a shared pool: `2 + 2·partySize`, counted at run start with bots, plus the difficulty adjustment. Boss kill +2. Cap `RIFT_LIVES_CAP = 12`. Any member's death costs one life, bots included.
- **Death hook** `riftOnDeath(world, victim, killer)` runs after the existing `killShip` bookkeeping and after the loot spill.
  - `lives > 0`: `lives--`, respawn in `RIFT_RESPAWN_SEC` (5 s), emit `lifeLost`.
  - Otherwise the pilot is **out for the floor**: `skillState.rWait = 1`, `respawnTick = MAX_SAFE_INTEGER`, emit `outOfLives`. The camera follows `RiftYou.followId`.
  - If every non-extracted member is dead and `lives === 0`: **party wiped**. Emit `partyWiped`; outcome `wiped`.
- **Respawn point** (`riftSpawnPoint`): the door in-point of a sealed room that holds an alive party member, otherwise `party.anchor`. Jitter 60–120 px on open tiles.
- **Medic Field Revive** also revives `rWait` pilots (free, no life cost). It skips `rOut`, which is fix #5.
- **Leaving** during the run: `removePlayer` spills the leaver's carried caches (no priority), and a bot takes the seat if fill is on.

### 4.7 Portals, extraction, floor swap, run end

- **Descend** (`portal` 0 closed → 1 open → 2 departing; zone r 160).
  - Trigger: a human ship in the zone, or any ship if the party has no alive human. `departTick = tick + 20 s`, reduced to +3 s once every alive human is in the zone. Emit `departing`. There is no cancel.
  - At `departTick`: `pendingFloor = floor + 1`, and each alive member gets +50 score.
- **Extract** (boss floors, `extractOpen`; zone r 140).
  - Each alive human ship in the zone accumulates `skillState.rExtract += 1/180` per tick, decaying 2/180 per tick outside.
  - At 1:
    - `secureCarried(world, ship)`, which emits `lootSecured`;
    - `detachAll`, `alive = false`, `respawnTick = MAX`, `rOut = 1`;
    - +100 score, emit `extract`;
    - push to `rift.extracted`.
  - The ship stays in `world.ships` for the scoreboard. The Room marks `RoomPlayer.extracted` and switches that player to spectator snapshots.
- **Final floor.** The boss clear opens only Extract, labelled "Exit". `victoryTick = tick + 45 s`. Outcome `cleared` at `victoryTick`, or earlier once every active human has extracted.
- **Floor swap** (`Sim.enterFloor`, private, at the end of `step()` before `stepMatch`, same Sim):
  1. `map = buildMatchMap({…, floor: f})`. Assert the dimensions match; set `world.map = map`.
  2. Clear enemies, projectiles, gems, deployables and **in-world loot**. Carried caches stay on the ships. Clear side `ramHits`/`pierceMem`.
  3. Reset `world.pve`: `wave = riftTier(f)`, `bossAlive = false`, `mem = {}`. New `rift.rooms`. Anchor = entrance; `seen` = entrance bit; `portal = 0`; `extractOpen = false`; `floorStartTick = tick`.
  4. Every non-extracted ship: detach, clear `rWait`, respawn at the entrance ring with `RIFT_FLOOR_INVULN_SEC = 3`.
  5. `riftFloorInit(world)` places dormant packs. Emit `floorStart{floor}`.
- **Outcomes** (`stepMatch` ends the match when `rift.outcome !== 'running'`):

  | Outcome | When | Winner |
  |---|---|---|
  | `cleared` | final boss dead and the victory lap is over (or all extracted after the final clear) | team 0 |
  | `extracted` | no active human remains, and none was wiped | team 0 |
  | `wiped` | party wiped | −1 |
  | `abandoned` | host `/end` → `Sim.abandonRift()` | −1 |

- **Loot security in the rift.** Caches are secured at extraction. At run end, alive pilots' carried caches are secured **only if the outcome is `cleared`**. Wipe or abandon loses everything unsecured.

### 4.8 Room layer (ROOM)

- **`beginPlaying`:** `new Sim({ gameType: 'dungeon', subMode: 'coop', mode: 'teams', teamCount: 1, floors, matchSeconds: 0, pveIntensity, friendlyFire, lootMult, lootSeed, … })`. Everyone goes to team 0. `rebalanceBots` runs in the lobby only.
- **Bot class** complements the party: an Artificer if the party has none, otherwise the least-used class in the party.
- **`sendMatchStart`** adds `gameType`, `subMode`, and `floor = world.dungeon?.floor ?? 0`.
- **When a `floorStart` event is drained:**
  1. Drop the positional events queued before it.
  2. Send `{type: 'floorStart', floor, tick}` to every watcher.
  3. Call `brain.onFloorChange?.()` for every bot.
  4. Apply queued class swaps.
  5. Add pending drop-ins (replacing bots via `syncBots`), then send them `matchStart`.
  6. Force a snapshot this tick.
- **Class changes** during a run are queued: "Class change applies at the next floor."
- **`summary().live`:** `floor`, `floorsTotal`, `lives`, `scoreline = "Floor 3/6 · 7 lives"`, `timeLeftSec = −1`.
- **`buildResult`:** `rift: RiftResult` with per-player status (extracted / survived / lost / left).
  - Awards: **Delver** (deepest floor), **Treasure Hunter** (chests opened), Exterminator, Field Medic, Battle Station.
  - Result chat lines (fix #23): "RIFT CONQUERED — all 6 floors cleared!", "Everyone extracted on floor N.", "Party wiped on floor N — unsecured loot lost.", "Run abandoned on floor N."
- **`noteEvents` chat lines:** "Floor 4 — Prism Vaults", "The Hive Matriarch awakens!", "X extracted from floor 3 with 5 caches", "Rift unstable — hunters inbound".

### 4.9 Rift bots (`ai/riftGoals.ts`, AI)

Priorities, evaluated before roaming:
1. Inside an ARMING or SEALED room: fight (the fallback goal is the room centre).
2. Follow the leader: the lowest-playerId alive, free human in the party. Stay 200–450 px behind; afterburn past 1000 px. The existing battle-station attach logic still applies.
3. No alive human: go to the lowest-depth main-path room that isn't CLEARED; once `portal ≥ 1`, go to the portal.

Other rules:
- Bots never extract, never pick up loot, and never trigger a descent while the party has an alive human.
- Retreat home means `party.anchor`.
- `nav.ts` rebuilds when `map.rev` changes. `onFloorChange()` clears path, goal and target.

**`coop.ready` flips only when `bots.test` "4 normal bots clear floor 1 of seed 1234 within 6 sim-minutes" passes.**

## 5. Objective modes spec (Arena + Warzone)

### 5.1 Map features (`sim/objectives/features.ts`, OBJECTIVES)

`buildMatchMap` for arena/warzone calls `generateMap(seed, teamCount)`, which is unchanged, so v0.2 maps stay byte-identical. For objective sub-modes it then calls `placeObjectiveFeatures(map, subMode, seed)`, which:
- uses only `new Rng(((seed | 0) ^ 0x0b1ec7ed) >>> 0)`;
- recovers base centres as the centroid of each team's `map.spawns`;
- carves WALL/ROCK → EMPTY and never touches TILE_BASE or the 2-tile border;
- finishes with `connectPoints(map, featureCentres)` (new `map.ts` export wrapping `ensureConnected`).

| Sub-mode | Features | Placement |
|---|---|---|
| ctf | `flagStand` × teams (index = team) | base centroid + 192 px toward the map centre. Carve a 4-tile disc. `radius` = capture radius 90. |
| zones | `zone` × n, n = clamp(teams + 1, 3, 5) | index 0 **Core** at the map centre. Flanks A–D on a 1300 px ring at the angles *between* adjacent bases (2 teams: base0 angle ± π/2; 5+ teams: every (T/(n−1))-th between-angle). Carve a disc of radius + 2 tiles, plus 3 cover rocks (r 1.3 tiles, 110–160 px from the centre). Radius 200. |
| hotpoint | `hotSite` × 8 | site 0 at the centre. Others rejection-sampled: ≥ 900 px from every base centroid (FFA: ≤ 2600 px from the centre instead), ≥ 700 px apart, ≥ 400 px from the border. Spacing relaxes ×0.85 every 400 failures. Carve 9.5 tiles plus 3 cover rocks. Radius 240. |

The wire never carries this geometry. The renderer and bots read `map.features`.

### 5.2 Sim integration (SIM hooks; OBJECTIVES implements them)

- **Constructor:** normalize the config (see §8 `isLegalCombo`), then `buildMatchMap`, then `createWorld`, then `pveInit`, then `objectivesInit(world)`. That sets `world.objective` (null for deathmatch).
- **`step()`:** `… stepProjectiles → stepObjectives → stepRift → stepLoot → bounty → enterFloor → stepMatch`. A rift and an objective never coexist.
- **`stepMatch`:** if `world.objective` is set, copy `teamPoints` into `teamScores` (never rebuilt from `ship.score`) and delegate to `objectiveEndCheck(w)`, which returns `'continue' | 'ended'` and sets the winner.
- **`spawnShip`:** the first line is `objectiveRelease(w, ship)`, which drops a carried flag at the pre-teleport position. With no `at`, use `riftSpawnPoint` in a dungeon, else `objectiveSpawnPoint` if non-null, else the default.
- **Pass 1:** `speedMult *= objSpeedMult`. **Pass 3:** recharge `*= objRechargeMult`.
- **`turrets.ts`:** `isValidHost` uses `objMaxTurrets(world, host)`, and `tryAttach` returns false for carriers.
- **`skills.ts` Blink:** range × `CTF_CARRIER_BLINK_MULT` for carriers.
- **Flags:** `stepObjectives` ORs `SHIPFLAG_CARRIER` (128) into `ship.flags` after pass 3.
- **Client prediction:** `speedMult = hostSpeedMult × carrierSpeedMult(view.flags)`.

### 5.3 Capture the Flag (2–4 teams)

- **Flags:** one per team, `home | carried | dropped`.
- **Pickup:** an alive, **non-turret** ship within radius + 26 px of an enemy flag (home or dropped); the nearest wins.
  - Picking up cancels spawn invulnerability. One enemy flag at a time.
  - A carrier with more than 1 turret shakes off the extras, keeping slot 0 (the **gunner seat**, `CTF_CARRIER_MAX_TURRETS = 1`).
- **Return:** a teammate touching their own dropped flag returns it instantly (+20). A dropped flag auto-returns after 20 s.
- **Capture:** the carrier comes within 90 px of its own stand **while its own flag is home**.
  - The team gets +1 capture, the flag returns, the carrier gets +100.
  - Earlier runners of this steal, and teammates within 900 px, get +30 each.
- **Drop:** on death, leave, respawn or class swap, at the last position.
- **Carrier rules:**
  - Speed ×0.88; ×0.82 with one gunner. Blink ×0.5.
  - **Flag Overload:** after 60 s of continuous carry, recharge ×0.5; after 90 s, ×0.
- **Personal score:** steal +15 · return +20 · carrier kill +25 · defend kill +5 (victim within 700 px of own stand or own dropped flag) · capture +100 · assist +30.
- **End:** first to the limit. At time-out, most captures. On a tie, **sudden death** (+180 s, next capture wins), then a draw.

### 5.4 Control Zones (2–8 teams; Arena, and Warzone under swarm)

- **Presence:** alive ships inside the radius, turrets included. Body multiplier: 1 → ×1, 2 → ×1.5, 3+ → ×2.
- **Capture:** neutral → owned in 8 s solo (4 s with 3). An enemy-owned zone is first decapped to neutral at the same rate.
- **Contested:** ships from 2+ teams inside, so nobody progresses.
- **Decay:** after 3 s empty, partial progress decays at 0.125/s.
- **Points:** each owned zone gives its owner +1 point every 2 s, even while contested.
- **Warzone:** ≥ `ZONE_SWARM_BLOCK = 3` enemies inside blocks capture progress. Points still tick.
- **Personal score:** a completed capture gives +15 to each contributor present in the last 3 s. A neutralize gives +10. Working the zone gives +1 per 2 s (the `objTicks` stat).
- **End:** reach the limit. At time-out, most points. On a tie, +60 s up to 3 times, then a draw.

### 5.5 Hot Point (2–8 teams or FFA; Arena only in v0.3)

- One active zone, r 240. Capture takes 5 s solo (same body multiplier). An uncontested owner gets +1 point/s. A contested owner earns nothing but keeps ownership.
- **Relocation:**
  - Every 60 s. At T − 10 s, `world.rng` picks the next site: ≥ 1400 px from the current one and not one of the last 2. Emit `hotWarn`; `view.hot.next` is set.
  - At T, the zone moves to the new site as neutral and arms after 3 s. Emit `hotMoved`.
- **FFA:** the owner is a player; 2+ players inside is contested. Points go to `playerPoints`. FFA spawns avoid anything within 800 px of the active site.
- **Personal score:** capture +15; +1 per 2 s inside while your side holds, caps or contests.
- **End:** reach the limit. At time-out, if the point is contested or a non-owner is capping, **overtime** runs until 1 s after that stops (cap 60 s). Then most points wins. On a tie, FFA compares `ship.score`, then it's a draw.

### 5.6 Swarm pressure in Warzone (PVE)

`objectiveAnchors(world)` returns active zones with weight 2. `findSpawnCenter` anchors on one with probability anchorWeight / (aliveShips + anchorWeight), keeping the same 1000–1500 px ring and `spawnPointOk`. No anchoring when `pveIntensity` is 0.

### 5.7 Wire, HUD, render, bots, room

- **Wire:** `MatchView.objective` holds dynamic state only and rides the JSON tail (≈ 200–250 B, built once per `prepare`). New event `{t: 'objective', …}`, which is global.
- **HUD (CLIENT):** the top-centre strip branches on `match.objective.mode`.
  - CTF: team flag chips (home / carried with carrier name / dropped with return timer), captures n/limit, and the overload countdown when *you* carry.
  - Zones: Core/A–D chips with owner fill, capper progress ring, contested and swarm badges; points n/limit.
  - Hot: owner chip, progress, "moves in 0:42", the next site at ≤ 10 s; FFA shows the top 3.
  - A centre capture bar when you're inside a zone. Banners from `objective` events.
- **Render (RENDER):** a pooled `objectiveLayer` after `mapLayer` and before gems.
  - Stands with an animated pennant. A carried pennant trails behind the carrier in the **flag's** team colour. A dropped pennant with a return ring.
  - Zone pads: dashed neutral ring, owner fill, capper arc, contested flicker, a letter label.
  - Hot point: pad, beam, move ring, faint candidate sites, and a ghost of the next site.
  - A glow on carriers. Minimap icons. Off-screen pointers.
- **Bots (`ai/objectiveGoals.ts`):**
  - `objectiveGoal(world, me, rank)` returns `{x, y, score, hold, targetShipId?}` and joins `decide()` as mode `'objective'`.
  - rank = the bot's index among alive teammates sorted by ship id.
  - While committed to an objective, fight scores for targets more than 800 px away are ×0.6.

  | CTF situation | Score |
  |---|---|
  | carrier heads to own stand; fight ×0.3; never attaches | 1.9 |
  | own flag carried: nearest 3 hunt the carrier | 1.5 |
  | own flag dropped: nearest 2 return it | 1.4 |
  | enemy flag dropped: nearest 3 grab it | 1.3 |
  | defender role (rank % 5 ∈ {2, 4}): own stand if > 600 px, else hold 400 px | 0.9 |
  | attacker role (rank % 5 ∈ {0, 1}): enemy stand (+0.3 if ≤ 1 defender nearby) | 0.85 |
  | flex role (rank % 5 = 3): escort own carrier 150 px behind | 0.8 |

  Turret rolls prefer our carrier (×2).
  - **Zones:** preferred zone = (rank + team) % n. Score 0.95 × (1 − d/5000) when the zone isn't ours or is under threat. Hold 0.6 inside an owned assigned zone. +0.3 when contested.
  - **Hot:** rank % 10 < 7 converge (score 1.0). At ≤ 10 s before a move, rank % 5 < 2 pre-rotate to the next site.
- **Room:**
  - `buildResult` always uses the sim's objective points (fix #7). On early `/end`, the winner comes from points (FFA hot: `playerPoints`); a tie is a draw.
  - `MatchResult.objective`, and `PlayerScore.obj` from `world.objective.stats` (keyed by playerId, so leavers keep their stats).
  - Awards, objective ones first, max 5: CTF — Flag Runner (caps), Goalkeeper (returns), Carrier Killer. Zones / Hot — Anchor (objTicks), Point Breaker (caps + neutralizes), King of the Hill (hot hold seconds).
  - Chat: "Crimson captured Azure's flag! 2/3", hot moves, overtime, sudden death. Zone flips are rate-limited to one per 5 s.
- **Ready gate:** each sub-mode flips `ready` only once the smoke "AI parity" run passes: 16 bots for 5 sim-minutes produce ≥ 1 `flagCaptured`, ≥ 2 `zoneCaptured`, or ≥ 1 hot capture + ≥ 2 `hotMoved`.

- **Cosmetic only.** Nothing touches `computeStats`, `ShipStats`, the ship record fields or hit sizes.
- **7 slots in v0.3:** `hull`, `weapon`, `turret` (per class / kit), and `engine`, `death`, `title`, `killicon` (shared).

### 6.4 Roll rules (`sim/loot.ts`, deterministic, `side(world).lootRng`)

1. `lootRng = new Rng(config.lootSeed ?? 0)`. `lootSeed` comes from `crypto` and is **never sent**. `world.rng` is never consumed, so determinism tests are unchanged.
2. **Chance:** `p = min(1, rule.chance[gameType] × config.lootMult)`. If `lootMult` is 0 or undefined, no loot rolls.
3. **Rarity:** `CACHE_RARITY_W` restricted to rarities ≥ the floor. In a dungeon, weights of rarity ≥ 2 are multiplied by `riftRarityBoost(floor, pve)` = (1 + 0.15·(floor − 1)) × (Nightmare ? 1.5 : 1), then renormalized.
4. **Set:** `MODE_SET_SHARE = 0.4` gives `SET_FOR_TYPE[gameType]`; otherwise `common`.
5. **Caps:**
   - Non-personal caches per match: Arena/Warzone `min(72, 8 + 4·humans)`; dungeon per floor `4 + 2·humans`.
   - Personal drops are exempt (the floor layout bounds them).
   - World cap `MAX_LOOT = 64`: at the cap, evict the oldest lowest-rarity drop below epic.
6. **Anti-farm `lootMult`**, computed by the Room and updated on human join and leave via `sim.setLootMult`:
   - ≥ 2 humans: 1.0.
   - 1 human: dungeon 1.0, arena 0.35, warzone 0.5.
   - Offline: 1.0.

### 6.5 Carry, spill, secure

- **Pickup:** touch distance is ship radius + 22 px. The ship must be alive, **human** (bots never pick up), not attached as a turret, and below `carryCap` (8; dungeon 24). The reservation must be respected, and the nearest eligible ship wins. Emit `lootPickup`.
- **Life:** 90 s for rolled drops, 45 s for spills; personal drops last the whole floor. Blink during the last 10%. Friction is `0.08^dt`, and drops stop at walls.
- **Beacon:** a ship with ≥ 4 caches, or any epic-or-better cache, shows on every radar (`Snapshot.carry`).
- **Spill:** in `combat.killShip`, `Sim.removePlayer` and team change.
  - Tokens spill highest rarity first, 60–180 px/s scatter, 45 s life, `droppedBy = victim`.
  - A non-ally killer gets 2 s priority. Allies, the swarm and self-kills get none.
  - Tokens keep their set and source. Emit `lootSpill`.
- **Secure:**
  - Dungeon extraction: `secureCarried` emits `lootSecured`, and the Room banks the tokens.
  - Match end: the Room calls `sim.takeCarried(pid)` for alive ships. Arena/Warzone always; dungeon only when the outcome is `cleared`.

### 6.6 Debrief crates, pity, shards (Room at `enterResults`, pure rolls in `profile/rolls.ts`)

- **Eligibility:** a human who played ≥ 120 s (`matchJoinTick`), in a match that lasted ≥ 180 s. Dungeon exception: also eligible after clearing ≥ 1 floor.
- **Crates:** base 1.
  - Arena/Warzone: +1 for a win (team win, or top 3 in FFA).
  - Dungeon: +1 per floor cleared (max +3), +1 for a full clear.
  - Crate rarity uses `CRATE_RARITY_W`; the set is the mode set 40% of the time, else Salvage.
- **Pity:**
  - `pity[gameType]` counts crates without an epic-or-better reveal. The 12th is forced epic from the mode set.
  - `pityLegendary` counts crates in any mode. The 60th is forced legendary from the current mode's set.
  - Resets on the matching reveal.
- **Identity roll:**
  1. Pool = `lootPool(set, rarity)`. If empty, step down a rarity.
  2. Pick uniformly. If owned, reroll once.
  3. Still owned: a duplicate, worth `SALVAGE_VALUE[rarity]` shards.
  4. Items are applied sequentially, so there's no double-new within one grant.
  5. The RNG is `Rng(fnv1a(grantKey + '|' + profileKey))`, so a retried grant rolls the same items.
     **M2 amendment (integration):** the server salts this seed with fresh CSPRNG bits per roll (`Rng(hash32(fnv1a(…), r1, r2))`, `ProfileService` `saltedGrantRng`). Every input above is known to the client, so the unsalted stream let a modded client predict and steer its crates (§7.4 "Predictable loot"). Retries re-apply the already-rolled grant and a replayed key returns the recorded grant, so nothing depends on re-rolling. See ARCHITECTURE.md §3c.
- **Shards:** 5 + 1 per full minute (cap +25) + 10 for a win + 10 for MVP (top scorer, if human) + duplicate values. Cap 999,999. They are spent on crafting in v0.4.

## 7. Profile, ProfileStore, security

### 7.1 Profile (versioned JSON, `PROFILE_VERSION = 1`)

The exact TypeScript is in §8.2. Contents:
- `owned`: starters are implicit and never stored. Unknown ids are preserved but ignored.
- `shards`, `loadout` (`shared` + `byClass`).
- `fresh` (NEW badges, ≤ 64).
- `pity` (per game type), `pityLegendary`.
- `stats`, `recent` (≤ 20), `updatedAt`.
- Size: about 2–4 KB when fully collected.

**`normalizeProfile(raw, now)`** never throws:
- Non-objects become `defaultProfile`.
- Malformed entries are dropped, and shards are clamped to [0, 999999].
- Loadout entries that are unknown, the wrong slot or class, or not owned fall back to the starter.
- `v > PROFILE_VERSION` gives `writable: false` for the session, so an older server never clobbers newer data.
- It does not use `loadJSON`'s shallow merge.

**Pure ops** (`profile/profile.ts`):
- `equip(p, slot, itemId, shipClass?)`: `''` means the starter; the item must be owned, fit the slot, and be for that class or kit.
- `markSeen(p, ids)`.
- `resolveLoadout(p, shipClass)`: returns a `CosmeticLoadout` with starters omitted.
- Crafting and salvage arrive in v0.4.

### 7.2 ProfileStore and backends

`src/shared/profile/store.ts` is a frozen, synchronous interface (§8.6). It is injected as `ZoneOptions.profiles`. **Room never touches storage.** Everything goes through `RoomHost.grantLoot` → `ProfileService`.

| Backend | Owner | Notes |
|---|---|---|
| `server/profile/sqliteProfiles.ts` `createSqliteProfileStore(dbPath)` | AUTH | Its own `DatabaseSync` on the same file, with `journal_mode = WAL`, `busy_timeout = 5000`, **`foreign_keys = ON`**. Asserts `user_version ≥ 2`; AuthService is constructed first and migrates. |
| `client/profile/LocalProfileStore.ts` | CLIENT | localStorage key `voidswarm.profile.device`, blob `{v: 1, profiles: {local}, ledger: string[≤100]}`, every access wrapped in try/catch. |
| `MemoryProfileStore` (in `store.ts`) | LOOT | For tests and smoke. |

**SQLite:**
- `MIGRATIONS[1]` (exact SQL in §8.9). `SCHEMA_VERSION` stays `MIGRATIONS.length`, so it becomes 2 automatically.
- `load`: `SELECT profile_json, profile_rev`. Bad JSON returns null and is logged.
- `save`: `UPDATE … SET profile_json = ?, profile_rev = profile_rev + 1 WHERE id = ? AND profile_rev = ?`. Zero rows throws `ProfileConflict`.
- `commitGrants`: `BEGIN IMMEDIATE`; per entry `INSERT OR IGNORE INTO loot_ledger` (0 changes means false, skip); then `UPDATE`; then `COMMIT`.
- Ledger rows older than 30 days are pruned at startup and every 24 h.
- `profile_json` stays NULL until the first change, so `auth.test` "profile_json NULL after registration" still holds. The `user_version toBe(1)` assertion becomes `toBe(SCHEMA_VERSION)`.

**Server wiring** (`server/index.ts`): `profiles = auth ? tryCreate(dbPath) : undefined`, passed to `new Zone`. If creation fails, account pilots get a session-only in-memory profile (`persisted: false`) and the UI shows "Loot won't be saved this session".

### 7.3 Grant flow

1. **Hello.** `ProfileService.attach(user)`: key = `accountId`, or `'local'` offline, or null for an online guest. Load, normalize, then send `{type: 'profile', profile, persisted}` right after `welcome`. **Online guests never get a `profile` message.**
2. **Equip / seenItems.** Handled by the **Zone**, not forwarded to the Room. Flow: pure op → `store.save` → push `profile` → `room.onProfileChanged(user)`, which pushes a `roomState` with the new `cosmetics`. Mid-match equips apply immediately.
3. **`beginPlaying`:**
   - `matchId = host.newMatchId()` = `${bootId}:${n}` (bootId is a random base36 id at Zone start).
   - `lootSeed = host.randomSeed()`, `lootMult`, `gameType`.
   - Set `p.matchJoinTick` for each player.
4. **During play.** `lootSecured` tokens go into `bank[profileKey]`. `lootSpill` increments `spills`.
5. **`enterResults`:**
   - For each human, build `GrantInput`:
     - `grantKey = ${matchId}#${profileKey}#${seq}`. `profileKey` = accountId, `'local'`, or `guest:${playerId}`. `seq` = how many times this key has been granted in this match (fix #17).
     - `tokens = bank ∪ sim.takeCarried(pid)`, plus `crateRolls`, `shards`, `won`, `cachesLost`.
   - Call `host.grantLoot(entries)`: one `commitGrants` transaction, and **it never throws** (fix #18). On failure it logs, queues the batch, retries on the next 3 housekeeping passes (idempotent by key), and after that tells the users "Loot could not be saved".
   - Then broadcast `matchEnd` (with `lootHighlights`), send each human `lootGrant`, and post a system line for legendary reveals.
6. **Leave mid-match.** Grant the secured bank with `crateRolls: 0` **before** `sim.removePlayer` spills the carried caches.
7. **Guests.** The server rolls against an empty profile and sends `lootGrant {persisted: false}`. The client applies it to the device profile with `applyGrant`, and patches its own `PlayerInfo.cosmetics` locally (the guest sees their own look; others see starters). The device ledger drops duplicate `grantKey`s.

### 7.4 Security

| Risk | Rule |
|---|---|
| Predictable loot | `SimConfig.lootSeed` from `crypto.getRandomValues`, **never sent**. Identity rolls happen server-side at grant time. |
| Forged intents / messages | `validate.ts` whitelists `intent ∈ {lobby, play, watch}`. `quickPlay`, `equip` and `seenItems` are added to `KNOWN` with shape checks (itemId string ≤ 40, ids array ≤ 64 strings ≤ 40, slot in `COSMETIC_SLOTS`). `MSG_CLASSES` in `user.ts`: quickPlay → general + action + announce; equip → general + action; seenItems → general. The ProfileService also rate-limits to 20 ops per 10 s per user. |
| Spectator ghosting | Cloaked ships are never sent to spectators. Watch is refused from the same address as an active player. Plain positional ghosting through a second device is accepted (documented). |
| Class / team swap teleport + heal | Arena/Warzone class swap while alive happens in place (position, velocity and energy fraction kept, no invulnerability, turrets detached, flag dropped). Team swap spills carried caches and drops the flag. Dungeon class swaps are queued to the next floor. |
| Farming vs bots | `lootMult` solo penalty; per-match caps; crate time gates (120 s played / 180 s match); bots never pick up or receive grants; host `/end` before 180 s voids crates. |
| Double grants / lost grants | Ledger primary key `(account_id, grant_key)`; join sequence in the key; `commitGrants` is the only write at match end; retry queue. |
| Newer profile clobbered | `v > PROFILE_VERSION` makes the profile read-only for the session. |
| Multi-process writes | The rev check; a single server process is assumed and documented in ARCHITECTURE §3c. |
| Client-known dungeon layout | Floors are generated from the public seed, so room locations are knowable. Chest contents are server-side. Accepted. |
| Alt accounts bypass the solo penalty | Accepted risk, documented. |
| Guest duplicates | Guests roll against an empty server profile, so device duplicates aren't rerolled. Accepted. |
| Long-running pid overflow | Codec v4 widens playerId to u32 (ship and loot records). |

  if (def.slot !== slot) return false;

  if (def.slot === 'turret') return def.kit === SHIP_CLASSES[shipClass].turret.id;
  return true;
}

/** 32-bit FNV-1a of a string (grant RNG seeds). */
export function fnv1a(s: string): number {
  let h = 0x811c9dc5;
  for (let i = 0; i < s.length; i++) { h ^= s.charCodeAt(i); h = Math.imul(h, 0x01000193); }
  return h >>> 0;
}
/** Order-sensitive 32-bit mix of integers (floor seeds: hash32(seed, floor, parties)). */
export function hash32(...xs: number[]): number {
  let h = 0x9e3779b9;
  for (const x of xs) {
    h = Math.imul(h ^ (x | 0), 0x85ebca6b);
    h ^= h >>> 13;
    h = Math.imul(h, 0xc2b2ae35);
    h ^= h >>> 16;
  }
  return h >>> 0;
}

/** Effective game type (Room always sets config.gameType; the fallback keeps v0.2 tests meaningful). */
export function gameTypeOf(config: SimConfig): GameType {
  return config.gameType ?? (config.pveIntensity > 0 ? 'warzone' : 'arena');
}
export function subModeOf(config: SimConfig): SubMode {
  return config.subMode ?? (gameTypeOf(config) === 'dungeon' ? 'coop' : 'deathmatch');

  return !!world.dungeon;

## 10. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Scope: v0.3 is about the size of v0.2 again, across 9 owners | Slips; half-integrated modes | Four independently shippable milestones; `ready` gating hides unfinished sub-modes; each gate needs bots to pass a test first |
| Contract churn after the freeze | Rework across modules | v0.4 slots (`rival`, `escort`, feature kinds, `MAX_PARTIES`, `OwnedItem.src 'craft'`) are reserved now; unions are append-only; new fields are optional |
| Single-threaded server tick with many sims (≈ 4 ms each) | Tick overruns, rubber-banding | `MAX_PLAYING_ROOMS = 6`; bots-only abort; idle house rooms have no Sim |
| Synchronous SQLite on the tick thread | Hitches at match end | One transaction per match; equip rate limit; no per-tick I/O; retry queue instead of blocking |
| Bot competence gates modes (CTF carriers, rift following) | Modes stay "Coming soon" | AI works in parallel against fake views; M3/M4 ship only when their gates pass; the Command UI already handles not-ready |
| Mid-floor tile mutation (rift doors) diverging between client and server | Prediction jitter or ghost walls | `applyRoomSeals` is the only mutation, pure and idempotent, driven by snapshot room states with a floor check; nav rebuilds on `rev` |
| Floor swap resets (interp / predictor / renderer caches) | Visual pops, stale sprites | A dedicated `floorStart` message before the new floor's first snapshot; `setMap` is re-entrant; `demo.ts` exercises it |
| Snapshot growth (rift + objective + loot in the tail) | Bandwidth at 32 viewers | Views are dynamic state only; `match` JSON memoized; loot section 14 B per cache, interest-filtered; `carry` only for carriers |
| Loot economy imbalance (dungeon yields ≈ 2× arena per hour) | One mode becomes the farm | The dungeon set is exclusive to the dungeon; all dungeon loot is at risk until extraction; the numbers live in `data/loot.ts` for tuning; solo multipliers |
| Farming vs bots or with alt accounts | Loot devalued | `lootMult`, caps, crate gates, no loot for bots; alt accounts accepted and documented |
| Cosmetic readability regressions (cloak, team identity) | Unfair PvP | Team colour kept on outline and projectiles; root-alpha rule; ΔE/saturation test; silhouette bounds |
| In-flight `TitleScreen.ts`/`styles.css` edit | Merge conflicts | CLIENT starts after it lands; one owner, one pass for all TitleScreen follow-ups |
| `EnemyKind` / `ClientMsg` Record exhaustiveness (`ENEMY_DEFS`, `ENEMY_COLORS`, `demo.ts`, `MSG_CLASSES`) | Typecheck breaks across owners | ARCHITECT lands placeholders together with the union; ROOM updates `MSG_CLASSES` in M1 |
| Multi-process server deployment | Profile write conflicts | Rev check plus ledger; single-process assumption documented in ARCHITECTURE §3c |
| Disconnects during a run | Lost unsecured loot, player frustration | Treated as leaving (secured bank granted, carried spills); a reconnect grace window is v0.4 backlog |
